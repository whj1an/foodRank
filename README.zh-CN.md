# 锐评 · Ottawa / Toronto 餐厅排行

我们吃过的餐厅排行榜，Ottawa 和 Toronto 分开记。两个人可以绑定账号，共用一份排行。

- **前端**：纯 HTML / CSS / JavaScript，不需要安装或打包，优先适配手机浏览器
- **后端**：[Supabase](https://supabase.com)（数据库 + 登录 + 图片存储，免费额度足够）
- **托管**：[Vercel](https://vercel.com)（免费）

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构 |
| `style.css` | 样式（颜色都在开头的变量里，十个等级的颜色在 `.lv-1` ~ `.lv-10`） |
| `app.js` | 所有逻辑 |
| `config.js` | 填 Supabase 的地址和公开 key，以及访客看谁的排行 |
| `supabase/schema.sql` | 数据库表、权限规则和图片桶，在 Supabase 里运行一次 |
| `supabase/upgrade-from-v1.sql` | 只在从第一版（从夯到拉）升级时用 |
| `manifest.webmanifest`、`icons/` | 手机「添加到主屏幕」用的名字和图标 |
| `docs/Requirements.md` | 需求文档 |

## 怎么用

- **地区**：点标题「锐评 ▾」切换 Ottawa / Toronto。两个地区各是一份排行，在 Ottawa 加的餐厅不会出现在 Toronto。
- **排行榜**：10 行（10 个等级），最下面是「待评」区。新加的餐厅先放进待评区，按添加时间从左往右排。
- **阅览**：点餐厅标签，弹出细节：等级、完整名称、图片（完整显示，不会被裁掉；左右滑，首尾相连：最后一张再往左滑就是第一张；点一下图片全屏看大图，再点一下关闭）、细节、谁添加的和谁排的。
- **搜索**：在搜索框里输入，只留下名称或细节里有这个词的餐厅（高亮，顺序不变），其他的先隐藏；点 × 清空。
- **排序**：点「编辑」，页面变成一张全新的空排行和待评区。按住餐厅拖到某一行（那一行会高亮，并显示它会吸附到的位置；夯拉样式里一个等级旁边有两行，按手指的高度决定放哪一行），松手，最后点左上角「完成」保存。同一批排的按添加时间从左往右，放在之前排好的前面。
- **添加**：搜索框右边的方形「+」，或者底部横栏的「添加」。填名称、最多 3 张图片（原始尺寸上传，第一张是封面）、任意条细节（每条最多 120 字）。
- **排错了**：在餐厅的细节弹窗里，「编辑」改名称 / 图片 / 细节，「放回待评」把它放回待评区重新排，「删除」删掉。
- **电脑上**（窗口宽度 960px 以上）：同一个网址会自动换成桌面版。排行榜更宽，一行放不下就换行，不用横着滑；没有底部横栏，添加按钮是右下角的圆形「+」，账户在右上角。点任意餐厅，细节在页面正中间弹出，图片用 ‹ › 按钮或键盘左右键翻，点图片可以全屏看大图，按 Esc 关闭。添加、删除、排序（用鼠标拖）和手机上完全一样。

### 评级样式

排行上方的按钮可以随时切换三种显示样式（每个人自己的浏览器记住自己的选择）。排行榜始终是 10 行：字母和数字样式每行一个等级；夯拉样式左边只用「从夯到拉」原本的 5 档，每档占两行（比如夯和顶级之间那一行算「夯」）：

| 夯拉（5 档） | 字母 | 数字 |
|---|---|---|
| 夯 | A、A- | 10、9 |
| 顶级 | B、B- | 8、7 |
| 人上人 | C、C- | 6、5 |
| NPC | D、D- | 4、3 |
| 拉完了 | E、F | 2、1 |

## 账号

- 只有两种身份：**用户**（登录了）和 **访客**（没登录）。
- 注册填 **用户名**（只能用英文字母和数字，3–20 位，不分大小写）和 **密码**（至少 6 位），登录也用这个用户名，不需要邮箱。
- 每个用户有一份自己的排行。访客能看但不能改；访客看谁的排行由 `config.js` 里的 `homeUser` 决定。
- **绑定**：绑定的两个人共用一份排行。任何一方添加的餐厅都会同时出现在两个人的待评区里，两个人都能排。两人同时排同一家时，以后点「完成」的那个为准。
- **取消绑定**：底部「账户」→ 最下面带下划线的小字「已绑定 xxx，取消绑定」。解绑后两人各自保留一份解绑前的完整排行，之后各记各的。
- 绑定在 Supabase 的 SQL Editor 里做一次（见下面第二步），网页上没有绑定按钮。

## 一、创建 Supabase 项目（约 10 分钟）

1. 去 <https://supabase.com> 注册，点 **New project**
   - Region 选 **Canada (Central)**
   - 数据库密码随便设一个复杂的并记下来（网页里用不到）
2. 左边栏 **SQL Editor** → **New query** → 把 `supabase/schema.sql` 全部内容粘进去 → **Run**
   - **从第一版（从夯到拉）升级？** 先运行 `supabase/upgrade-from-v1.sql`（会删掉旧的餐厅和评价，登录账号保留），再运行 `schema.sql`。
   - 已经建好的库不要再运行第二次 `schema.sql`。
3. 左边栏 **Authentication** → **Sign In / Providers** → **Email**：
   - ⚠️ **必须关掉 "Confirm email"**。网站用「用户名」登录，背后是一个不会收信的内部邮箱，开着邮箱确认就没人能登录。
4. 左边栏 **Project Settings** → **API Keys**，复制两样东西填进 `config.js`：
   - **Project URL**（`https://xxxx.supabase.co`，在 Project Settings → Data API 里也能看到）
   - **Publishable key**（`sb_publishable_...`）或旧版的 **anon public** key
   - ⚠️ 不要填 secret / service_role key（网页会拒绝启动）
5. `config.js` 里的 `homeUser` 填访客默认看谁的排行（用户名）。

## 二、注册和绑定

1. 打开网站，你和她分别点右上角「登录 / 注册」→「注册」，填用户名和密码
2. 在 Supabase 的 **SQL Editor** 里运行（换成你们注册的用户名）：

   ```sql
   select public.bind_users('第一个用户名', '第二个用户名');
   ```

   第二个人会搬进第一个人的排行，TA 之前加过的餐厅也一起带过去。
3. 刷新网页，底部「账户」里显示「已绑定 …」就对了

## 三、本地试一下

```bash
python3 -m http.server 5173
```

打开 <http://localhost:5173>。本地用的也是线上那个 Supabase 数据库。

## 四、发布到网上（Vercel）

1. 在 GitHub 新建一个仓库，把这个文件夹推上去
2. 去 <https://vercel.com> 用 GitHub 登录 → **Add New… → Project** → 选这个仓库
3. Framework Preset 选 **Other**，其他都不用改 → **Deploy**
4. 得到一个 `https://xxx.vercel.app` 的网址

以后每次 `git push`，Vercel 会自动更新网站。

> **改了 `style.css` 或 `app.js` 之后**：把 `index.html` 里 `?v=` 后面的数字加 1（比如 `style.css?v=5` → `?v=6`），不然手机浏览器可能一直用旧的缓存。

> **改动需要新的 SQL 时**：先在 Supabase 里运行 SQL，再推代码。新网页配旧数据库是用不了的。

## 五、手机上用

- **Android**：Chrome 打开网址 → 菜单 → **添加到主屏幕**
- **iPhone**：Safari 打开网址 → 分享 → **添加到主屏幕**

## 注意事项

- 网站是公开可看的：任何拿到网址的人不用登录就能看到排行、图片和细节，所以别写太私人的内容。任何人也都能注册自己的账号（有一份自己单独的排行）。
- 图片按原始尺寸保存。Supabase 免费版有 1 GB 存储，大概够几百张手机照片。每张图还会自动生成一张小缩略图给排行榜用。
- iPhone 的 HEIC 照片：Safari 上传时一般会自动转成 JPG；如果某张打不开，页面会提示，换一张 JPG 或 PNG 就行。
- Supabase 免费项目**连续 7 天没人访问会自动暂停**，去控制台点一下 Restore 就恢复，数据不会丢。
- 定期在「账户」里点「导出备份」存一份 JSON（图片存的是链接）。

## 常见问题

**注册时提示「Supabase 不接受内部邮箱格式」**
用户名在背后会变成 `用户名@fromhang2la.app` 这样的内部邮箱。如果 Supabase 拒绝这个域名，在 `config.js` 里加一行 `accountEmailDomain: '别的域名.com'` 换一个。注意：**换了以后，之前注册的账号就登录不了了**，所以最好在大家注册之前定好。

**有人忘了密码**
没有邮箱，所以没法自己找回。在 Supabase 的 **SQL Editor** 里帮 TA 重设（换成 TA 的用户名和新密码）：

```sql
update auth.users set encrypted_password = extensions.crypt('新密码', extensions.gen_salt('bf'))
where id = (select id from public.profiles where username = 'TA的用户名');
```
