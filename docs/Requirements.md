Version 0.1

# 大纲

这是一个关于餐厅的排序网页，数据存于云端，桌面用户和手机用户都可以进入同一页面，每个用户也可以通过用户名登陆进入自己的账号并且对自己的数据进行增删改的操作。

# 手机浏览器端

这个部分主要适配手机界面的浏览器界面，任何的二级窗口、弹窗都应该显示在可视范围内。

## 主界面

分为Ottawa和Toronto两个地区的版本，不同地区的版本分别存储，并且选完地区之后当前页面的所有添加餐厅和删除餐厅的操作都在这个地区之内，不允许在Ottawa地区添加的餐厅出现在Toronto的页面上，反之依然。

**顶部标题**：顶部`header.bar`中最左侧为标题：“锐评“，右边是一个向下的小三角（标题和这个小三角靠在一起），点开为一个下拉菜单，菜单中可以选择是Ottawa还是Toronto地区；最右边为登陆/注册按钮。

**搜索**：header.bar下面是一个居中的搜索框搜索图标在搜索框内的右侧，搜索框的右侧是一个方形的添加按钮，按钮中间只要一个`+`就行，他的作用是弹出一个**二级页面**添加餐厅。

**排序**： 随后是从夯到拉的主要页面，是一个一行一行的排序列表，这个排序列表一共有3中类型，但是所有类型都是一共只有10行（等级）；在最下面那一行有个待选区，所有新添加的新餐厅都应该按添加时间顺序从左往右排序。排序列表分别为编辑模式和阅览模式，在阅览模式下用户点击标签时会跳出细节弹窗，弹窗顶部左侧用和名字等高的方格，内部默认显示数字（1-10）排序级别并且按照从夯到拉的颜色填充方格背景，方框后方显示显示标签完整名称，如果名称超出页面宽度，将自动会将名字折叠并添加小三角，用户点击三角将展开展示完成名称。

名称下方图片部分（默认显示用户第一个添加的图片，如果添加的图片多于1张，用户可以左右滑动来阅览其他图片（第三章往右滑动回到第一张），并且在图片框下部用小字显示当前图片序号和总图片数量（如果只有一张图那就不显示），图片下方显示用户添加的细节部分，在细节下方小字显示由谁添加和由谁排序。

在排序列表的右上角（列表外部）有一个编辑（保存）按钮，点击编辑后进入编辑模式，这时候应该整个页面变成只有全新的排序列表（即以前拍好的标签消失）和还没放如列表的待选列表，用户可以通过按住待选餐厅并滑动到排行中的指定位置，手指划过的地方应该会有高亮效果，高亮也需要有**吸附效果。抬起手指之后，餐厅标签应该自动吸附到高亮位置，并且每个等级中的餐厅标签按照添加时间顺序从左往右显示。待用户全部添加完毕之后，用户需要点击左上角完成按钮，此刻网页需要保存刚刚用户添加的餐厅标签，并且将它们从左往右添加到列表中，以前添加的标签也在此时显示出来，并且旧标签应该按照时间顺序放在新标签后面。点击完成之后用户不允许滑动任何标签。如果添加的标签数量超过显示宽度，应该维持原大小并且增加横向瀑布流。



添加按钮：用户一般通过移动端chrome进入网站，所以在页面底部固定一个横栏，左中右分别为：主页、添加和账户。点击主页将实现回到顶部的效果。点击添加将会弹出一个从下往上的浮动页面，用于用户添加新标签，这个页面最上部是**名称：**用户可以添加标签的名称，名称下面是添加图片块，初始状态下是一个白色半透明的加号，用户点击之后可以上传相关照片，上限3张，照片为原始尺寸，并且在待评区和排行榜中以添加的第一张图片作为封面。在添加图片的下方有一个可以添加细节的区块，用户点击右侧的加号可以添加细节文本框，用户可以在内输入至多120个中文字符的评价，然后在最下方是按钮完成。用户点击完成之后该标签会自动排到待评横栏。

用户点击账号按钮会弹出账号信息，显示用户名和统计信息（一共添加过多少个评价）

**账号**：现在默认只有用户和访客两种类型（目前用户只有两个），这两个账号将绑定并且将会共享同意排行榜和库。例如A和B绑定，那么A添加的标签出现在A界面的待评框内，并且也会同时出现在B的待评框内。两人可以同时拖动放置评价，但是按照这两个用户点击 **完成**的先后顺序来保存最终的标签等级。在账户中心，绑定中的任意一方可以在最下方点击加了下划线的小字：以绑定`用户名`，取消绑定。取消绑定后，A和B均继承解绑前的排行信息。
